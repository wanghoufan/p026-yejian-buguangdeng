# PRODUCT_PLAN｜夜间补光灯 V1.1

- Plan Version：PRODUCT_PLAN_V1.1（Change B 修订：2026-09-19 用户裁决移除 A11 关闭倒计时功能，回退 V1.0 无倒计时行为；A 类范围 11→10 项，所有倒计时相关条目作废）
- PROJECT_PHASE：DEVELOP
- Product Goal：采用「定位 A：第二台手机伴侣补光」。把用户的备用手机或第二台手机变成随手可用的全屏柔光灯；主手机负责拍摄，第二台手机负责补光。用户无需专业灯具、账号或联网，打开 App 即可获得稳定、可调、持续的屏幕光源。
  - 唯一对外定位文案：「夜间补光灯把第二台 Android 手机变成独立补光灯：主手机负责拍摄，第二台手机负责发光，无需配对、不可远程控制。」
  - README 的产品定位段和商店文案首句必须逐字使用上述原句，不得另写容易暗示远程协同的同义版本。
- Target Users：
  - 拥有备用 Android 手机，需要给自拍、合影、视频通话或近距离拍摄补光的个人用户。
  - 与朋友同行，希望由一台手机拍摄、另一台手机补光的用户。
  - 在夜间、室内、车内、餐厅等低照度场景中，需要临时柔光但不愿携带专业灯具的轻量用户。
  - 本版本不面向专业摄影棚、商业直播间或需要精确色温和显色指数控制的专业用户。
- Problem：
  - 单台手机同时承担拍摄和屏幕补光时，屏幕朝向、可用面积和操作空间互相冲突。
  - 系统手电筒光线集中、偏硬，近距离照射容易刺眼并产生明显阴影。
  - 专业补光灯需要额外购买和携带，对临时、低频场景成本过高。
  - 普通纯色页面缺少快速配色、亮度控制、状态记忆和持续常亮能力。
  - 用户需要的是“拿起第二台手机就能用”的工具，而不是账号、社区、相机或复杂灯光系统。
- Core Value：
  - 第二台手机就是伴侣补光灯：主手机专心拍摄，副手机独立发光，无需配对、不可远程控制。
  - 打开即亮，核心操作不经过首页、登录页或模式选择页。
  - 通过预设色、自定义颜色、色彩强度和屏幕亮度，覆盖日常近距离补光。
  - 完全本地、离线、无账号，降低使用门槛并保护隐私。
  - 控制面板可手动或自动收起，尽可能保留完整发光面积。
  - 支持竖屏、横屏和 Android 大屏宽视口基础使用。
  - 支持一键恢复暖白默认状态。
- User Flow：
  1. 用户准备主手机进行自拍、合影、视频通话或近距离拍摄。
  2. 用户拿出安装了「夜间补光灯」的第二台 Android 手机。
  3. 打开 App，Splash 结束后立即进入全屏补光画布，并恢复上次有效状态；首次启动使用暖白、100% 色彩强度和 100% App 屏幕亮度。
  4. 用户可在竖屏或横屏下使用；横竖屏切换后，当前颜色、强度、亮度和 Tab 状态保持不变。
  5. 用户轻点补光画布，呼出底部毛玻璃控制面板。
  6. 用户直接选择预设颜色，或切换到色轮选择自定义颜色。
  7. 用户分别调整色彩强度与当前 App 的屏幕亮度，观察人物面部和环境效果。
  8. 用户需要回到初始补光状态时，可一键恢复暖白默认值。
  9. 用户轻点面板外区域、向下拖动，或停止操作满 5 秒后，控制面板收起；持续拖动控件期间不得自动收起。
  10. 用户把第二台手机放置在人物正前方或侧前方，主手机继续拍摄。
  11. 补光期间屏幕保持常亮；App 进入后台时交还系统亮度控制，返回前台时恢复 App 内保存的亮度。
  12. 用户主动退出后，下次打开恢复最后一次有效的颜色、强度、亮度和 Tab；控制面板默认收起。
- Functional Scope：
  - 本版本严格包含以下 10 项 A 类范围（原 A11 关闭倒计时已经 Change B 移除）；A 类表示定位成立和交付验收所必需的范围，缺少任一项均不视为 V1.1 完成。
  - **A1｜打开即补光**
    - App 启动后直接进入补光画布，不设置欢迎页、首页、登录页或额外确认步骤。
    - 首次启动默认暖白、色彩强度 100%、App 屏幕亮度 100%、控制面板关闭。
    - 再次启动恢复最后一次有效的颜色、强度、亮度和 Tab，但控制面板仍默认关闭。
  - **A2｜全屏补光与沉浸显示**
    - 当前显示颜色覆盖全部可用屏幕区域。
    - 状态栏隐藏，Android 导航栏在系统允许范围内尽可能隐藏。
    - 控制面板关闭时不保留业务按钮、文字、水印或其他遮挡光源的元素。
    - 补光期间保持屏幕常亮。
  - **A3｜轻点呼出与手动收起控制面板**
    - 轻点补光画布呼出底部毛玻璃控制面板。
    - 轻点面板外区域或向下拖动可关闭面板。
    - 操作 Tab、预设色、色轮、Slider 和恢复默认控件时不得误关闭面板。
    - 面板展开时，上方区域继续显示当前补光颜色。
  - **A4｜8 个固定预设颜色**
    - 提供暖白、中性白、冷白、奶油、桃粉、玫瑰粉、氛围紫、冰蓝共 8 个预设。
    - 预设以 4×2 圆形色块展示，点击后立即生效，无确认按钮。
    - 当前预设具有清晰但轻量的选中状态。
    - 选择预设不得自动重置色彩强度。
  - **A5｜色轮自定义颜色**
    - 控制面板提供「预设颜色 / 色轮」两个 Tab。
    - 用户可在 HSV 色轮上连续选择颜色，拖动过程实时更新补光画布。
    - 色轮显示当前选色位置。
    - 仅切换 Tab 不得改变当前补光颜色或其他参数。
  - **A6｜色彩强度与 App 屏幕亮度双调节**
    - Color Intensity 控制白色到目标颜色之间的插值，不等同于屏幕物理亮度。
    - Screen Brightness 仅调整当前 App Activity 的屏幕亮度，不写入系统全局亮度。
    - 两个 Slider 均需连续、稳定、可预测，不得出现跳值、闪跳或拖动失效。
    - App 进入后台或 inactive 状态时恢复系统控制；回到 active 状态时重新应用保存的 App 亮度。
  - **A7｜本地记忆与离线可靠性**
    - 本地保存目标颜色、色彩强度、App 屏幕亮度和最后使用的 Tab。
    - 不保存控制面板展开状态，再次启动时默认收起。
    - 持久化数据缺失、损坏或越界时安全回退到默认值。
    - 无网络、无账号、无后端时全部 A 类能力仍可使用。
    - 连续补光过程中不得因系统自动息屏而中断。
  - **A8｜控制面板自动收起**
    - 面板打开后，以最后一次有效交互结束为起点计时，连续 5 秒无操作则自动收起。
    - 点击、滑动、切换 Tab、选择颜色或恢复默认均重新开始 5 秒计时。
    - 手指按下或正在拖动色轮、Slider、Sheet 时暂停自动收起；交互结束后重新计时。
    - 自动收起只改变面板状态，不改变颜色、强度、亮度或 Tab。
  - **A9｜竖屏、横屏与大屏宽视口基础适配**
    - Android 竖屏和横屏均列入正式支持范围，不再锁定仅竖屏。
    - 横屏和大屏宽视口下必须保持补光画布铺满，全部控制项可见、可达、可操作，无裁切、重叠或屏外控件。
    - 横竖屏切换不得重置颜色、强度、亮度、Tab 或面板状态。
    - 大屏仅要求响应式基础可用，不要求平板专属交互、双栏界面或像素级专项设计。
  - **A10｜一键恢复暖白默认**
    - 控制面板提供单次点击即可触发的「恢复暖白默认」操作。
    - 操作后立即恢复：暖白 `#FFF2E2`、预设颜色来源、色彩强度 100%、App 屏幕亮度 100%、预设颜色 Tab。
    - 恢复结果立即显示并持久化；重新启动后仍为恢复后的状态。
  - **A11｜关闭倒计时**：已移除（2026-09-19 Change B，用户裁决不提供倒计时功能，回退 V1.0 无倒计时行为）。
- Out of Scope：
  - 不使用主手机远程控制第二台手机；不做二维码配对、蓝牙配对、局域网配对或多手机同步。
  - 不提供相机、拍照、录像、美颜、滤镜、构图辅助或视频通话能力。
  - 不控制 Torch、闪光灯或外接摄影灯。
  - 不提供专业 Kelvin 色温、RGB 数值、照度、显色指数或设备校色能力。
  - 不提供音乐律动、动态灯效、渐变动画、呼吸灯、频闪或场景自动识别。
  - 不提供账号、登录、会员、广告、支付、社区、云同步或跨设备状态同步。
  - 不建设 Supabase、数据库、业务后端或依赖网络的服务。
  - 不申请任何 Android `uses-permission`；Activity 亮度和屏幕常亮必须使用无需运行时授权的应用内能力。
  - 不把 iOS、桌面端或 Web 端列入本版本交付验收范围。
  - Android 大屏仅保证响应式基础可用，不提供平板专属布局、多窗口专项优化或大屏独有功能。
  - 不提供关闭倒计时、定时结束补光或任何后台定时能力（2026-09-19 Change B 移除原 A11）。
  - 不承诺替代专业摄影灯，不承诺不同手机屏幕具有一致的色温、亮度或显色表现。
  - 不在本版本重新设计已经冻结的方案 C 视觉语言；仅允许为横屏、大屏、可用性、系统兼容性和缺陷修复作必要调整。
- Technical Approach：
  - 延续现有 Expo SDK 57、React Native、TypeScript 和 Android 单页应用架构，不引入后端。
  - 移除 `app.json` 与 Android Activity 的仅竖屏锁定，允许 Android 竖屏和横屏旋转。
  - 继续以单一 Light Canvas 作为根视觉层，通过当前目标颜色和色彩强度计算最终显示色。
  - 控制面板采用基于可用宽高的响应式约束；横屏和大屏宽视口不得依赖固定竖屏高度。
  - 使用集中配置维护 8 个冻结预设，避免 UI、状态和测试数据不一致。
  - 色轮继续使用本地生成的 HSV 色盘资源和位置指示器；触摸坐标统一使用测量后的页面坐标换算。
  - Slider 统一使用组件级测量缓存与 `pageX` 换算，并保留必要节流。
  - 通过单一状态源管理目标颜色、显示颜色、色彩强度、屏幕亮度、Tab、Sheet 和自动收起计时。
  - 自动收起使用可取消、可重置的 5 秒本地计时器；控件持续交互期间暂停计时。
  - 一键恢复默认复用统一的默认状态常量。
  - 使用本地存储保存允许持久化的状态；读取时执行类型、范围和颜色格式校验。
  - 通过 Android Activity 级亮度接口控制当前 App 亮度；生命周期变化时恢复或重新应用，不修改系统全局设置。
  - 使用无需权限的窗口常亮能力保证连续补光。
  - 删除主发布 Manifest 中现有的 `INTERNET`、存储、悬浮窗、振动和 `WRITE_SETTINGS` 等 `uses-permission`，最终发布 APK 权限清单为 0 项。
  - 不引入 `fetch`、Axios、XHR、WebSocket、WebView、联网 SDK 或其他远程请求路径。
- Data / API：
  - 不使用远程 API、云数据库、用户账号或网络请求。
  - 本地持久化数据：
    - `targetColor`：合法 HEX 颜色或等价的受控颜色值。
    - `colorIntensity`：0–1 的有限数值。
    - `screenBrightness`：0–1 的有限数值。
    - `activeTab`：`preset` 或 `wheel`。
  - 当前会话临时状态：
    - `sheetAutoCloseDeadline`：面板自动收起截止时间。
  - 不持久化：
    - 控制面板展开状态。
    - 面板自动收起计时。
    - 临时拖动坐标。
    - App 生命周期状态。
    - 系统原始屏幕亮度。
  - 本地数据读取失败、字段缺失、类型错误或越界时，逐字段使用安全默认值，不阻塞 App 启动。
  - 推荐继续使用既有存储键 `fill-light:v1:last-state`；若数据结构发生不兼容变化，必须提供迁移或兼容读取。
  - 最终 Android 权限清单：无，发布 APK 中不得包含任何 `<uses-permission>`；不得申请 `INTERNET`、`CAMERA`、`RECORD_AUDIO`、`WRITE_SETTINGS`、`SYSTEM_ALERT_WINDOW`、存储、通知、定位、蓝牙或其他运行时权限。
- Key Assumptions：
  - 核心使用情境中，用户拥有一台可作为光源的第二台或备用 Android 手机。
  - 用户接受手动摆放第二台手机，不要求主手机远程控制。
  - 手机屏幕提供的光线足以改善近距离、低照度场景，但不承担专业摄影灯效果。
  - 8 个预设加 HSV 色轮足以覆盖轻量用户的主要颜色需求。
  - 用户能够凭画面观感手动调节颜色、色彩强度和亮度，不需要专业参数。
  - 打开即亮、无账号、无网络依赖比功能数量更重要。
  - 现有 V1.0 真机验收证明基础交互和 Android 技术路线可行；V1.1 的主要变化是产品定位和验收口径收敛，而非重做技术架构。
  - 不同 Android 设备的屏幕材质、系统亮度策略和导航栏行为存在差异，产品只保证功能逻辑一致，不保证物理光效完全一致。
- Competitor / Research Summary：
  - 本轮定位依据现有产品、仓库证据和 V1.0 真机验收结果整理，尚未执行独立外部竞品桌面研究。
  - 可替代方案主要包括系统手电筒、浏览器纯色页、通用屏幕灯 App 和便携式实体补光灯。
  - 相比系统手电筒，本产品强调大面积屏幕柔光、颜色选择和较低刺激性，而不是高强度点光源。
  - 相比浏览器纯色页，本产品增加启动即用、预设色、色轮、双维度调节、自动收起、横屏与大屏基础适配、一键恢复、常亮、沉浸显示和本地状态记忆。
  - 相比专业实体补光灯，本产品优势是零额外硬件和随手可用，劣势是亮度、色准、散热和续航受手机硬件限制。
  - 相比复杂灯光 App，本产品选择单用途、离线和无账号，避免遥控、动态灯效与内容功能稀释“第二台手机伴侣补光”定位。

- Risks：
  - **定位误解**：用户可能把“第二台手机伴侣补光”理解为主手机可以远程控制副手机。缓解：README 与商店文案逐字使用唯一定位原句。
  - **横屏布局风险**：现有配置锁定竖屏，横屏和宽视口可能出现 Sheet 过高、控件裁切或色轮溢出。缓解：移除方向锁定，采用可用宽高约束，并覆盖竖屏、横屏和大屏三类 viewport。
  - **自动收起误操作**：用户停顿观察颜色时，面板可能在拖动中关闭。缓解：所有有效操作重置计时，持续按压或拖动期间暂停自动收起。
  - **权限残留**：当前生成的 Android Manifest 含与正式产品无关的权限。缓解：发布前删除并以最终 APK 权限清单为准验收。
  - **物理效果差异**：不同屏幕的最大亮度、色偏、PWM、护眼模式和自动亮度策略不同。缓解：不承诺绝对色温和照度；真机覆盖至少两种 Android 设备。
  - **亮度系统限制**：部分 ROM 可能限制 Activity 亮度或沉浸模式。缓解：只使用 Activity 级能力，失败时保持可用并记录设备差异，不申请系统全局权限。
  - **长时间发光风险**：高亮度可能带来耗电、发热和 OLED 残影。缓解：提示长时间使用可降低亮度。
  - **触摸冲突**：色轮、Slider、Sheet 拖拽、画布点击和自动收起可能互相抢占事件。缓解：冻结手势优先级，并纳入自动测试和真机回归。
  - **状态损坏**：异常退出或历史数据可能产生非法状态。缓解：持久化前后均校验，按字段安全回退。
  - **范围膨胀**：多手机遥控、相机、后台常驻和动态灯效容易被视为自然延伸。缓解：全部明确列入 Out of Scope，新增必须走后续 Change Request。
- DoD：
  - **范围一致性**
    - 10 项 A 类范围全部实现并逐项通过验收（原 A11 倒计时已经 Change B 移除，不得出现在实现与文案中）。
